# Почему нет версии для iOS (и что с этим делать)

## Короткий ответ

На iOS приложение такого класса **в принципе невозможно** в автоматическом
режиме: Apple не предоставляет сторонним приложениям доступ ни к одному из
трёх источников данных, на которых построена оценка ёмкости.

## Что именно закрыто

| Данные | Android | iOS |
|---|---|---|
| Счётчик заряда (charge counter, мкА·ч) | `BATTERY_PROPERTY_CHARGE_COUNTER` — публичный API | Нет. `UIDevice.batteryLevel` даёт только SOC 0–100 % с шагом 5 % |
| Мгновенный ток (`CURRENT_NOW`) | BatteryManager + sysfs | Нет. IOKit/IOPSKeychain отдают только «Serial», «DesignCapacity» и пр., и то не всё; ток не экспортируется вовсе |
| Полная/паспортная ёмкость от контроллера (`charge_full`, `charge_full_design`) | sysfs `/sys/class/power_supply/*` (на большинстве устройств читается без root) | Закрыто. Даже Jailbreak-твики читают IOKit-ноды, недоступные App Store SDK |
| Фоновый опрос датчиков | Foreground Service + WorkManager | Нет фонового исполнения с нужной частотой; BGAppRefresh непредсказуем |

Ключевое следствие: на iOS известен только **SOC** (числитель), а знаменатель —
фактическая полная ёмкость — не измерить никак. Кулон-счёт и интегрирование тока,
то есть вся математика этого приложения, остаются без входных данных.

Что видит сам iOS в Настройках → Акумулятор → «Состояние аккумулятора» — это
оценка самой ОС из её внутреннего fuel gauge, наружу API нет.

## Стратегия порога: ручной ввод как fallback

Приложение уже спроектировано так, что методика не привязана жёстко к Android:
`ResolveDesignCapacityUseCase` имеет приоритетную цепочку источников паспортной
ёмкости, включая **ручной ввод пользователя**, а `MeasurementMethod` содержит
значение для «введено вручную». Это открывает единственный честный вариант
iOS-версии:

1. Пользователь разряжает iPhone до отключения, затем заряжает до 100 %
   *выключенным* или сразу после включения, засекая время/считая passed mAh
   с внешнего USB-измерителя (или берёт цифру из отчёта Analytics →
   «Last Charge Capacity», если устройство её показывает).
2. Вводит полученное значение полной ёмкости и паспортную ёмкость модели.
3. Приложение считает износ % = actual / design и ведёт историю деградации.

Это неудобно и грубо (±10–15 %), но это единственное, что iOS позволяет
без джейлбрейка. UI-слой приложения (Compose Multiplatform) переиспользуется;
заменяется только data-слой: вместо sysfs/BatteryManager — форма ввода и
хранилище истории.

## Если всё же нужен Android-подобный опыт

Реалистичные альтернативы вне App Store:
- **Mac Catalyst / macOS**: на macOS часть IOKit-статистики батареи читается
  (`ioreg -rn AppleSmartBattery` даёт AppleRawMaxCapacity/DesignCapacity) —
  десктопная версия могла бы работать по методу C полноценно.
- **Jailbreak-only твит**: чтение IOKit-нод возможно, но это не продукт.

Итого: Android-версия остаётся основной; iOS — только ручной сценарий,
macOS — потенциальный полноценный порт метода C.
